This artifact tracks the Agentic Salesforce Delivery Pipeline end to end. It gets updated and reused at each readback across the engagement, it isn't rebuilt from scratch every session.

Current phase: the BA process, how a business requirement becomes a ready to groom user story. This phase covers both of Experian's discovery pipelines side by side, CPQ and Salesforce Platform, since both feed the same BA process. Later phases, story grooming, development, testing, deployment, get their own discovery sessions and land in this same document as they're designed.

What discovery showed us

Three sessions, one shared problem underneath all of them.

CPQ · Jul 27
  • Input is an Excel config template: config flow, attribute dependencies, pricing model, DRM IDs.
  • Stories are config workbooks, not "as a user" format. They mirror how the product is configured.
  • Acceptance criteria exist implicitly in the story structure, not as a formal section.
  • Agile Accelerator, a custom Salesforce package, runs stories and sprints today.
  • No agent has direct Salesforce access today. Everything is manual.
Salesforce Platform · Jul 28
  • Cases flow through CRM Analyst triage, then a BA escalation gate, then a project or BAU split.
  • Lucid and a legacy Excel "Disco doc" are the working discovery tools.
  • Some AI is already in informal use: a custom GPT for BRDs, a ChatGPT built solution pack.
  • All of it is manual copy paste into Salesforce today.
Dev & deployment · Aug 18
  • Local, SFDX-based development confirmed: a developer's agent builds a plan from the story and sandbox state, gets human sign-off, then implements and self-corrects — never touching production directly.
  • Real PoCs today are already HTML/CSS mockups with mock data and no live backend — exactly matching this pipeline's existing PoC pattern.
  • CPQ work starts from the config workbook and enters Salesforce as a case; product hierarchy records must exist in DRM before story development, roughly 80% of the time.
  • Salesforce confirmed as the single source of truth for every pipeline artifact — stories, PoCs, meeting notes, Lucid charts. SharePoint was explicitly avoided; Bitbucket never came up.
  • Agile Accelerator keeps ownership of conflict detection and promotion to UAT/production — the pipeline hands off cleanly rather than replacing that tooling.
  • Claude Code is the dominant dev tool today, already 80-90% adopted across the team, with Codex used by some for lower token cost.

All three sessions point at the same root problem: getting the right context in front of the right AI session. That's the hard part, not the AI itself.

Backup tooling continuity (AgentForce Vibes)

Sadar's team wants Claude Code as primary, with AgentForce Vibes — Salesforce's rebranded Einstein for Developers, also running on Claude Sonnet 4.5 under the hood — as a backup if Claude Code credits run out mid-month. Vibes' skill format (.vibes/skills/) is structurally close to Claude Code's, and it supports adding remote MCP servers the same way, so this pipeline's skill logic is likely portable. Bitbucket access isn't a concern either way — VS Code's native git works with any publicly reachable git remote.

The real risk isn't the tool surface, it's the network: Vibes only connects to resources reachable via an unrestricted public URL — it explicitly does not work behind a VPN or private network. If Experian's Bitbucket or Lucid sit behind a corporate VPN or IP-allowlist, Vibes can't reach them as a fallback, regardless of MCP support. If Vibes ends up running inside a VDI, it's already on Experian's internal network, so this constraint may not apply the same way — that needs an actual test once Vibes is provisioned, not an assumption either way. Worth confirming before this gets promised to the team as a real backup path.

Skill distribution options

Five ways to get finished skill files onto every developer's machine, compared side by side. Experian is on Bitbucket, which rules out Claude's admin-console plugin sync — that mechanism only reads through the Claude GitHub App or a GitHub Enterprise App, with no Bitbucket or GitLab equivalent. Experian is confirmed on Claude Enterprise, which unlocks two of the options below that wouldn't otherwise be available.

Decided — 2026-08-21, by Experian's own team. Richard Joseph and Pavankumar Chinnareddy walked through this same comparison independently in the Agile Accelerator discovery session and selected Option 5, Salesforce-hosted: skill content stored as long-text fields on custom Salesforce objects, folder-structured and access-controlled, pulled at session start or when an agent connects to a work item. Their own reasoning — agents work significantly better with structured, relational data than flat files, and Salesforce's object model already fits that — validates rather than overrides the comparison below. This is a real build Cirrius now owes (the actual Salesforce object model for skill hosting), not a configuration change.

The dimension that mattered most in getting here: does the option actually reach the local, sandbox-based sessions this pipeline's developers run (SFDX against a dev sandbox, per-developer authentication)? One of the five — Organization Skills — only reaches claude.ai chat, the Desktop app's Chat and Cowork tabs, and cloud/Dispatch sessions. It doesn't reach a local session regardless of which interface opens it, which is why it's ruled out here rather than left as a live option — and Experian's own team independently confirmed the same finding from their side (their own GitHub-issue evidence matched Cirrius's research exactly).

Target architecture

This is a data pipeline, not a multi-team parallel workflow, so it's shown here as a straight-through flow rather than swimlanes. Several steps still have open questions, flagged where they occur. Not yet written up as a formal architecture doc — this tab is effectively step one of that writeup.

1 Trigger

Two paths fire the same pipeline: a weekly scheduled batch via AWS EventBridge, similar in shape to Experian's existing Jenkins cron though not a direct replacement of it — or an on-demand run, where Salesforce hits Experian's existing EC2 endpoint (no new DNS or firewall work) which invokes the Lambda function directly via a scoped IAM role, routed over a VPC endpoint so traffic never crosses the firewall boundary.

↓
2 Pull from source systems

Each source authenticates through its own Secrets Manager entry and a dedicated integration account — never named-user credentials. Salesforce / CPQ uses a Connected App with JWT bearer auth.

  • Salesforce / CPQ — account-visibility-scoped security model. Typically contributes opportunity stage and amount, quote/CPQ status, and product or pricing changes.
  • ServiceNow — typically contributes aggregate case data: open/closed/in-progress counts and ticket volume trends, not individual ticket comments.
  • Gong — typically contributes call and meeting transcripts and summaries tied to the account: talk points, sentiment, and follow-up items. Transcripts are already pushed to Salesforce at the task level; still deciding whether to connect to Gong directly or reuse that existing integration.
    Open
  • ZoomInfo — typically contributes firmographic and org-change signal: company size and structure, and contact/role turnover at the account. Which specific fields matter is still undefined, pending a BA assigned per source to define desired fields and synthesis instructions.
    Open
  • Medallia — typically contributes customer satisfaction and survey signal: CSAT/NPS scores, survey responses, and sentiment trends. Which specific slices matter is still undefined, pending a BA assigned per source to define desired fields and synthesis instructions.
    Open
  • Tableau / data lake — typically contributes usage and analytics data: product usage metrics and existing operational reporting. On-prem needs a VPC connection, Cloud may allow a direct API; the fallback is bypassing Tableau and querying the data lake directly.
    Open
↓
3 Delta vs. full refresh

Every run checks a single account-level "last run" timestamp. Unchanged sources return a "no change" signal rather than being reprocessed. A full refresh triggers on first run, a new account, or a just-merged account — Salesforce is the source of truth on merges: the losing account drops out of the pipeline entirely, and the winning account gets flagged for a full refresh. Proposed implementation: an account-level checkbox toggling delta/full, auto-set on merge.

Still open

Each source may need its own relevance window — e.g. Gong calls older than 30 days are likely irrelevant, while open opportunities aren't time-bounded at all.

↓
4 Synthesize each source individually

Each signal layer — each source's pulled data — is synthesized on its own first, before anything gets combined across sources.

↓
5 Controller merges against the prior COP

A controller compares the newly synthesized signals against the account's prior COP output (fed back in as an input) and updates only the sections that actually changed — sources with no new signal are left alone in the narrative. A template governs the output's shape: word count and section structure.

↓
6 Write to the Account 360 object

Final synthesized text — never raw source data — is written to a single custom object that's a child of Account in Salesforce: many records per Account, one Account 360 record per section of the account's story. Which section a record covers is set by its Record Type, each holding the synthesized signal for one category of account information:

  • Account Overview — general account health and relationship synthesis.
  • Opportunities — pipeline and deal signal.
  • Cases — support and service signal.
  • Revenue — financial signal.
Still open

Exact record-type-to-source mapping isn't detailed yet — e.g. which record type ServiceNow and Gong support-related content feeds into, versus which one CRM opportunity data feeds into — beyond these four record type names.

Supporting AWS infrastructure

Compute
  • Lambda — serverless, preferred over Experian's existing EC2/IIS/Jenkins pattern, which was judged too light for this payload.
Storage
  • S3 — transient batch storage, roughly 1GB per 1,000 accounts.
Secrets
  • Secrets Manager — fills a real gap; today's Jenkins credentials aren't externally accessible.
Scheduling
  • EventBridge — drives the weekly batch trigger.
