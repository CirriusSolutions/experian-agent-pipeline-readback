Agentic Salesforce Delivery Pipeline

Cirrius: Gavin Franklin  ·  Experian: James Weatherall, Mark Parysz, Sadar Yacob  ·  Current phase: BA Process  ·  This version: Aug 10, 2026

A living design document

This artifact tracks the Agentic Salesforce Delivery Pipeline end to end. It gets updated and reused at each readback across the engagement, it isn't rebuilt from scratch every session.

Current phase: the BA process, how a business requirement becomes a ready to groom user story. This phase covers both of Experian's discovery pipelines side by side, CPQ and non-CPQ, since both feed the same BA process. Later phases, story grooming, development, testing, deployment, get their own discovery sessions and land in this same document as they're designed.

What discovery showed us

Two sessions, one shared problem underneath both.

CPQ · Jul 27
  • Input is an Excel config template: config flow, attribute dependencies, pricing model, DRM IDs.
  • Stories are config workbooks, not "as a user" format. They mirror how the product is configured.
  • Acceptance criteria exist implicitly in the story structure, not as a formal section.
  • Agile Accelerator, a custom Salesforce package, runs stories and sprints today.
  • No agent has direct Salesforce access today. Everything is manual.
Non-CPQ · Jul 28
  • Cases flow through CRM Analyst triage, then a BA escalation gate, then a project or BAU split.
  • Lucid and a legacy Excel "Disco doc" are the working discovery tools.
  • Some AI is already in informal use: a custom GPT for BRDs, a ChatGPT built solution pack.
  • All of it is manual copy paste into Salesforce today.

Both sessions point at the same root problem: getting the right context in front of the right AI session. That's the hard part, not the AI itself.

Target architecture

Skills flowing from triage through discovery, story creation, PoC build, delivery, and deployment. CPQ and non-CPQ each run their own version through story creation and PoC build; development, testing, and deployment are shared. Triage through PoC Build are designed so far, click a tile for the detail.

After the story

Once the user story exists in Salesforce, all downstream work fetches from the story itself.

1
Prompt

"Build the CPQ config for BusinessIQ - UK Credit Reports & Images."

or: /cpq-skill BusinessIQ - UK Credit Reports & Images

Retrieves: the product's SharePoint folder, located by name, holding the Excel config template, prior meeting recordings, and any existing plan.md file, with the template read against the standard CPQ config template doc

Output

A structured, versioned config document, ready for the CPQ User Story Generation Skill.

Also produces

A plan.md file written back to that same SharePoint folder, tracked by multiple BAs across this product's configuration lifecycle. Updated, not replaced, each time someone touches this product, until the story exists.

↓

Prompt

"Write the user story for BusinessIQ - UK Credit Reports & Images from the latest config plan."

or: /cpq-user-story-skill BusinessIQ - UK Credit Reports & Images

Retrieves: the CPQ Skill's structured config document and this product's plan.md file from SharePoint, and the standard user story template doc

Output

A Salesforce-standard user story, written directly into Agile Accelerator, with acceptance criteria attached and linked back to the plan.md file. Including: "Given a case configured with Commitment Type = Yes and Commitment Base = Volume, when the Risk Report is selected, then VADs appear as sub-options and CATO/CAI eligibility reflects the membership rules." A formal acceptance-criteria line the story doesn't have today.

Backup tooling continuity (AgentForce Vibes)

Sadar's team wants Claude Code as primary, with AgentForce Vibes — Salesforce's rebranded Einstein for Developers, also running on Claude Sonnet 4.5 under the hood — as a backup if Claude Code credits run out mid-month. Vibes' skill format (.vibes/skills/) is structurally close to Claude Code's, and it supports adding remote MCP servers the same way, so this pipeline's skill logic is likely portable. Bitbucket access isn't a concern either way — VS Code's native git works with any publicly reachable git remote.

The real risk isn't the tool surface, it's the network: Vibes only connects to resources reachable via an unrestricted public URL — it explicitly does not work behind a VPN or private network. If Experian's Bitbucket, SharePoint, or Lucid sit behind a corporate VPN or IP-allowlist, Vibes can't reach them as a fallback, regardless of MCP support. Worth confirming before this gets promised to the team as a real backup path.
